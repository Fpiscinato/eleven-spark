# ElevenSpark - Gloucestershire 11+ (G7 FSCE) Grammar School Prep PWA

## Architecture & Deployment Context
- Target User: 9-year-old student (Year 5 UK) preparing for the Gloucestershire Grammar Schools Entrance Test (Pate's, Stroud High, Ribston Hall, Denmark Road, Crypt).
- Hosting & CI/CD: GitHub repository deployed as a static PWA on Cloudflare Pages / Workers (`wrangler.toml` compatible, SPA routing fallback).
- Tech Stack: React 18+, TypeScript, Vite, Tailwind CSS, Lucide React, Dexie.js (IndexedDB), KaTeX (math formulas), Zod (schema validation), Vite PWA plugin.

## Exam Rules (G7 FSCE - Gloucestershire, three papers in July at the end of Year 5)
1. Every question MUST have exactly 5 options (`A`, `B`, `C`, `D`, `E`).
2. Core Subjects: `english`, `maths`, `compass` (Across the Curriculum). Optional / bonus subjects: `vr` (Verbal Reasoning) and `nvr` (Non-Verbal Reasoning) - "Bonus Logic Gym - Not required for Glos FSCE" (`isOptionalSubject()` in `src/db/schemas.ts`).
3. Mock Papers (mirrors of the real FSCE):
   - **Adventure Paper** (`mock_paper_1`, ~50 mins): Section A (English Comprehension, Spelling, Punctuation, Best Word) -> Strict Section Lock -> Section B (KS2 Maths). Multiple choice.
   - **Beacon Paper** (`mock_paper_2`, ~50 mins): Section A (English written answers) -> Strict Section Lock -> Section B (Maths written answers). Written answers are typed into a box (`answerType: 'short_text'` + `acceptedAnswers`); the correct answer is only revealed after the child checks their answer.
   - **Compass Paper** (`mock_paper_3`, ~30 mins): Section A - Across the Curriculum, logical interpretation across 11 KS2 disciplines (Science & Experiments, History & Geography, Computing & Logic, Arts, Design, Music & Languages).
   - **Mini-Mock** (`mini_mock`, 20 mins): 12 + 12 mixed core questions.
   - Section Lock Rule: Once a student finishes Section A or the timer expires, they advance to Section B and CANNOT go back to view or edit Section A.
4. Compass questions are generated by `src/generators/compassGenerator.ts` and must be fully deducible from the stem/SVG, and every question must pass `childSafetyGuard` / `filterUnsafeQuestions`.

## Coding Standards
- Strictly typed TypeScript (no `any`).
- Never leave `TODO` placeholders or incomplete functions.
- UI must be child-friendly, high-contrast, tablet touch-friendly, with encouraging feedback in Practice Mode and realistic exam discipline in Mock Mode.

## Local Checks
- `npm run build` (runs `tsc -b` + `vite build`) - the only reliable type check (`tsc --noEmit` on the solution tsconfig is a no-op).
- `npm run lint`, `npx tsx scripts/audit-safety.ts` (child-safety + shape/integrity + Beacon written answers), `npx tsx scripts/audit-content.ts 3` (served bank, passages, empty answers).
- `node scripts/generate-icons.mjs` after bumping `APP_VERSION` (icons live in `public/app-icons/v<version>/`).
