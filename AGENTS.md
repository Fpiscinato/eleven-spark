# ElevenSpark - Gloucestershire 11+ (G7 FSCE) Grammar School Prep PWA

## Architecture & Deployment Context
- Target User: 9-year-old student (Year 5 UK) preparing for the Gloucestershire Grammar Schools Entrance Test (Pate's, Stroud High, Ribston Hall, Denmark Road, Crypt).
- Hosting & CI/CD: GitHub repository deployed as a static PWA on Cloudflare Pages / Workers (`wrangler.toml` compatible, SPA routing fallback). The deployment is done by **Cloudflare Workers Builds** (the repository is connected to the Cloudflare account) with build command `npm run ci` and deploy command `npx wrangler deploy`. There is **no GitHub Actions workflow** — the old one always failed for lack of secrets and only produced failure emails.
- Tech Stack: React 18+, TypeScript, Vite, Tailwind CSS, Lucide React, Dexie.js (IndexedDB), KaTeX (math formulas), Zod (schema validation), Vite PWA plugin.
- All user-facing copy is in **English** (the child is preparing for an English-language exam). Portuguese text is a bug, not a translation request.

## Exam Rules (G7 FSCE - Gloucestershire, three papers in July at the end of Year 5)
1. Every question MUST have exactly 5 options (`A`, `B`, `C`, `D`, `E`).
2. Core Subjects: `english`, `maths`, `compass` (Across the Curriculum). Optional / bonus subjects: `vr` (Verbal Reasoning) and `nvr` (Non-Verbal Reasoning) - "Bonus Logic Gym - Not required for Glos FSCE" (`isOptionalSubject()` in `src/db/schemas.ts`).
3. Mock Papers (mirrors of the real FSCE) - see `src/lib/exam.ts` for the live configuration:
   - **Adventure Paper** (`mock_paper_1`, ~45 mins): Section A (English Comprehension & Vocabulary, 22 min) -> Strict Section Lock -> Section B (KS2 Maths Fluency, 23 min). Multiple choice.
   - **Beacon Paper** (`mock_paper_2`, ~45 mins): Section A (English & Maths written answers, 25 min) -> Strict Section Lock -> Section B (Creative Writing Task, 20 min).
     - Section A questions are **typed into a box** (`answerType: 'short_text'` + `acceptedAnswers`); the correct answer is only revealed after the child presses "Check my answer". When the section is flagged `writtenMode`, the paper picks `short_text` questions first so the paper really is a written-answers paper.
     - Section B is a **creative writing task**: no multiple-choice question is generated for it, so it can never appear as a phantom "unanswered" mark. It is reported with the number of words written and an interactive 5-criterion rubric (1-4 marks each).
   - **Compass Paper** (`mock_paper_3`, ~40 mins): Section A - Across the Curriculum, logical interpretation across 11 KS2 disciplines (Science & Experiments, History & Geography, Computing & Logic, Arts, Design, Music & Languages).
   - **Mini-Mock** (`mini_mock`, 20 mins): 12 + 12 mixed core questions. It is **extra practice, not an official paper**: it is shown in its own "Extra practice" block, never among the three official papers.
   - Section Lock Rule: Once a student finishes Section A or the timer expires, they advance to Section B and CANNOT go back to view or edit Section A.
4. Compass questions are generated by `src/generators/compassGenerator.ts` and must be fully deducible from the stem/SVG, and every question must pass `childSafetyGuard` / `filterUnsafeQuestions`.
5. **NVR and VR never move the exam progress**: `computeRoadmap()` (`src/utils/roadmapCalculator.ts`) calculates every phase metric on the core subjects only, so optional bonus practice can neither raise nor lower the `%` of Phases 1, 2 and 3. Optional work is counted separately in `optionalAnswered` and labelled "Optional Bonus (Not in Glos FSCE Exam)".

## UX Rules (Phase 7.3.1)
1. **No-scroll practice screen** (`src/pages/PracticePage.tsx` + `src/components/exam/QuestionView.tsx`): the runner is a fixed-height flex column (`md:h-[calc(100dvh-133px)] md:overflow-hidden`) with a compact header (progress / timer / subject), a scrollable question area and a **footer that is always visible** with the "Confirm Answer" / "Next question" button. The page itself must never scroll on tablet or laptop.
2. **Timers freeze on the last answer**: answering the final question of a run finalises the clock (`stopTimers()` in `PracticeRunner` and in the mock engine) so the elapsed time and the stored session time are identical.
3. **Beacon creative writing** (`src/components/exam/BeaconWritingPanel.tsx`) is a guided 3-step flow: Read (prompt + planning timer) -> Write (text area + writing timer) -> Check (interactive checklist). The submit button only unlocks when **every** checklist box is ticked **and** the writing is saved. The panel must never loop: a submitted piece returns to the main practice panel and `resetKey` opens a clean, new task.
4. **Two levels of help after a wrong answer** (`src/components/exam/AnswerHelp.tsx`): "💡 Quick Explanation" (why this answer is right) and "🧠 Learn How to Solve (Tutorial)" (the concept, a 3-step method, the common trap and then "do this one yourself").
5. **Average time must be real thinking time** (`src/lib/timing.ts`): anything over `MAX_TRACKED_SECONDS` (300s) is an anomaly - it is capped when written to the database and ignored when averages are computed, so a tab left open can never distort "Avg Time".

## UX Rules (v1.7.5 - Action First)
1. **One runner for every question session**: `src/components/exam/PracticeRunner.tsx` is the ONLY runner. Quick Practice, the Mistake Clinic and the Mistake Bank all use it, so their screen size, two-column layout (`lg:` and up), fixed footer and spacing are identical **by construction**. Never build a second runner.
2. **Action-first Practice screen** (`src/pages/PracticePage.tsx`): the ▶️ Start Practice and ⚡ Quick 10 Mix buttons sit in the first card at the top of the page, with the selection summary (e.g. *"Maths • Mixed Topics • 10 Questions"*). Everything else lives in three **collapsible cards, closed by default** (`CollapsibleCard` in `src/components/ui.tsx`): ⚙️ Customise Practice, 🩺 Mistake Clinic & Mistake Bank (header shows the pending count + a "Fix Mistakes Now" button) and ✍️ Beacon Creative Writing Studio.
3. **One single confirmation to stop** (`src/components/exam/ConfirmEndSessionModal.tsx`): the Stop/Cancel/Exit button of a running session shows ONE alertdialog with exactly two buttons - "Continue Practising" and "End Session" - and the message *"Your answered questions are already saved"*. No double confirmation, no multi-step dialogs.
4. **The mobile bottom menu always shows where you are** (`src/components/AppShell.tsx`): the active tab has a coloured top bar, a filled indigo icon tile and a bold indigo label; the inactive ones have a neutral tile.


## Coding Standards
- Strictly typed TypeScript (no `any`).
- Never leave `TODO` placeholders or incomplete functions.
- UI must be child-friendly, high-contrast, tablet touch-friendly, with encouraging feedback in Practice Mode and realistic exam discipline in Mock Mode.
- Maths must be infallible: a question may never have two mathematically correct options, and a correct answer must never be shown with floating point noise (`0.8099999999999999`).

## Local Checks
- `npm run build` (runs `tsc -b` + `vite build`) - the only reliable type check (`tsc --noEmit` on the solution tsconfig is a no-op).
- `npm run lint`.
- `npm run audit` runs the five audits:
  - `npm run audit:safety` (`scripts/audit-safety.ts`) - child-safety, shape/integrity, empty stems/explanations, Beacon written answers, balanced KaTeX delimiters.
  - `npm run audit:maths` (`scripts/audit-maths.ts`) - **re-solves every maths question from its own stem** and proves the marked answer is correct, that no distractor shares its value, that no float noise leaks and that the `$` delimiters are balanced.
  - `npm run audit:content` (`scripts/audit-content.ts 3`) - served bank, passages, empty answers.
  - `npm run audit:fsce` (`scripts/audit-fsce.ts`) - the Gloucestershire model: the three official papers, the Beacon written answers, the 11 Compass disciplines and the proof that NVR/VR never move the phase progress.
  - `npm run audit:visibility` (`scripts/audit-visibility.ts`) - no invisible text (a colour is never used for both the background and the letters, in light **and** dark mode) and the base-10 version rule.
- `node scripts/generate-icons.mjs` after bumping `APP_VERSION` (icons live in `public/app-icons/v<version>/`, older folders are removed automatically). Bump `QUESTION_BANK_VERSION` too when the generators change, so the bank is re-seeded for the children.

## Versioning (base-10, digit by digit)
- The version is `major.minor.patch` and every part is a single digit (0-9): `1.7.4 -> 1.7.5 -> ... -> 1.7.9 -> 1.8.0 -> ... -> 1.9.9 -> 2.0.0`.
- `npm run version:bump` performs the bump (`scripts/bump-version.ts`): the last digit goes up, and when it would pass 9 it rolls over to 0 and carries into the digit on the left.
- The version is shown **only** in Settings (`src/pages/SettingsPage.tsx`).
